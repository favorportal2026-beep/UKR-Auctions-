# UA Auction Monitor 🇺🇦

Моніторинг державних аукціонів України за вашими критеріями. Автоматично збирає
лоти з **Prozorro.Sale** і **СЕТАМ**, фільтрує за збереженими пошуками
(регіон, ціна, площа, тип, знижка від оцінки тощо) і надсилає **сповіщення в Telegram**
про нові збіги. Фокус MVP — **нерухомість і земля**.

> Аналог інструмента моніторингу аукціонів UK, адаптований під українські джерела.

## Джерела

| Джерело | Що | Доступ |
|---|---|---|
| **Prozorro.Sale** | мала приватизація, банкрутство, активи банків, **нерухомість, земля** | відкрите API (ЦБД) |
| **СЕТАМ** | арештоване/конфісковане майно (примусовий продаж, дисконт) | відкриті дані (CSV, data.gov.ua) |

## Як влаштовано

```
collectors → нормалізація → Supabase → критерії → Telegram
```

Деталі архітектури, endpoint-и й відкриті завдання — у **[CLAUDE.md](./CLAUDE.md)**.

## Швидкий старт

1. **Supabase:** створіть проєкт, виконайте `supabase/schema.sql` у SQL Editor.
2. **Ключі:** `cp .env.example .env` і заповніть (Supabase URL/service_role,
   `SETAM_CSV_URL`, Telegram token/chat_id).
3. **Залежності й перевірка:**
   ```bash
   npm install
   npm run typecheck
   npm run collect -- --source=prozorro --dry-run   # переконатись, що мапінг ок
   ```
4. **Критерій:** додайте рядок у таблицю `criteria` (приклад — в кінці `schema.sql`).
5. **Повний прохід:**
   ```bash
   npm run collect
   ```
6. **Автоматизація:** додайте GitHub Secrets (ті самі імена, що в `.env`) —
   workflow `.github/workflows/collect.yml` запускатиме збір за розкладом.

## Статус

MVP-скелет. Два відкриті завдання перед продакшеном (обидва — у CLAUDE.md):
звірити мапінг полів Prozorro та закріпити колонки CSV СЕТАМ на реальних даних.
Веб-додаток (Vercel/Next.js) — наступна фаза.
