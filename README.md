# Аукціони.UA

Моніторинг продажу нерухомості та землі України з Prozorro.Sale й СЕТАМ.
TypeScript / Node 22, Supabase, Telegram, Next.js 14 і Mapbox.

## Можливості

- Збір активних лотів, оновлення наявних лотів до завершального статусу, архів.
- Каталог зі сторінками по 48 лотів, сітка/список, сортування й спільні фільтри з мапою.
- Мапа всіх результатів із кластерами, областями, супутником і мобільним списком.
- Відбір: Розглянути / Шорт-ліст / Торгуюсь, приховані лоти та нотатки; доступ із каталогу й мапи.
- Детальна картка `/lots/<uuid>` з описом, цінами, датами, кадастром і документами джерела.
- Збережені критерії, повний транзакційний перерахунок збігів, Telegram.
- Автоматичний вибір свіжого CSV СЕТАМ через CKAN; час оновлення й помилки на сайті.

## База

Новий проєкт: виконати `supabase/schema.sql` або застосувати міграцію
`supabase/migrations/20260918190945_ua_auction_monitor_complete.sql`.
Міграція ідемпотентна для наявної української схеми. Продуктові таблиці закриті
RLS без публічних політик; доступ і RPC дозволені серверному service_role.
У спільній базі UK/UA міграція змінює лише таблиці українського монітора.
Не запускати глобальний `supabase db push` проти спільної бази без узгодження її
повної історії міграцій: цей репозиторій не містить міграцій UK-продукту.

## Збирач

```bash
cp .env.example .env
npm ci
npm test
npm run typecheck
npm run build
npm run collect -- --source=prozorro --dry-run
npm run collect
npm run collect -- --no-notify --no-geocode
npm run refresh -- --limit=200
```

`refresh` звіряє відомі Prozorro-процедури за внутрішнім id; курсор окремий,
статуси/поля оновлюються без Telegram. Звичайний збір також перевіряє до
`PROZORRO_REFRESH_LIMIT` відомих процедур за запуск, поступово обходячи всі.
`npm run match` — розсилка наявних незаспoвіщених збігів, а не перерахунок.

GitHub Actions: Prozorro щодня 06:00 UTC, СЕТАМ щодня 07:00 UTC.
`SETAM_CSV_URL` — необов’язкове ручне перевизначення; порожнє значення вмикає
автовибір найновішого CSV. Стандартний CSV не містить площі, оцінки й дат торгів.
Лінки СЕТАМ резолвляться з HTML списку торгів, невідомий лінк не вигадується.
Розсилка збою/відновлення — через наявний Telegram-бот, повтор однакової помилки
приглушується. Для ручної перевірки workflow дозволяє вимкнути розсилку/геокодування
або запустити лише оновлення відомих Prozorro.

## Перевірки бази

`tests/rematch.sql` — інтеграційна перевірка у транзакції з відкатом: 1205 лотів,
збереження стану Telegram та зняття збігів після завершення/дедлайну.
Запускати лише в контрольованому середовищі: на час транзакції перерахунок
блокує інші перерахунки збігів.
