# Веб-дашборд (Фаза 2)

Next.js (App Router) дашборд для моніторингу держаукціонів. Читає ту саму базу
Supabase, що й колектор. Ходить у БД **лише з сервера** (`service_role`), тому
ключ не потрапляє в браузер і дані лишаються приватними (RLS закритий).

## Можливості

- **Лоти** (`/`) — картки з фільтрами (джерело, тип, критерій, регіон, пошук,
  «лише зі збігами»), бейдж дисконту від оцінки, посилання на лот.
- **Курація** — кнопка ✕ ховає лот (`lots.hidden = true`), ↩ повертає.
- **Критерії** (`/criteria`) — додати / редагувати / видалити / вмик-вимк.
- **↻ Перерахувати збіги** — застосовує поточні критерії до всіх зібраних лотів
  (колектор інакше матчить лише нові/змінені).
- Необов'язковий пароль-гейт через `APP_PASSWORD`.

## Локальний запуск

```bash
cd web
cp .env.local.example .env.local   # впишіть SUPABASE_URL і SUPABASE_SERVICE_ROLE_KEY
npm install
npm run dev                         # http://localhost:3000
```

## Деплой на Vercel

1. Vercel → **Add New → Project** → імпортувати цей репозиторій.
2. **Root Directory** = `web`.
3. **Environment Variables** (Production + Preview):
   - `SUPABASE_URL` = `https://kfltwtfekzddipjvrxwn.supabase.co`
   - `SUPABASE_SERVICE_ROLE_KEY` = service_role ключ (Supabase → Settings → API)
   - `APP_PASSWORD` = (необов'язково) пароль доступу до дашборда
4. **Deploy**. Далі кожен push у гілку деплоїться автоматично.

> `service_role` ключ — секретний; він лише в змінних оточення Vercel, у код і
> браузер не потрапляє. Тримайте `APP_PASSWORD` заданим, якщо не хочете, щоб
> будь-хто з посиланням бачив дашборд.
